# Accessibility review: Phase 2a (theme and accessibility sprint)

Date: 2026-10-20. Scope: all seven pages (Home, Services, Projects, BizCheck,
About, Contact, 404) at 320, 768 and 1280px, light theme. Standard: WCAG 2.2 AA.
Method: automated gate (axe-core via Chromium, static lint, behaviour tests, pixel
contrast measurement) plus the manual list in `checklist.md`, run with Chromium
emulation. Results below are observations from this run.

## Summary

| Area | Result |
|---|---|
| axe-core violations | 0 on every page at every width (24 nodes at the start of this task) |
| Static lint | 0 problems |
| axe "needs review" | 193 items, all justified; each verified by measured contrast |
| Keyboard walkthrough | Pass, with the mobile menu fixed in this task |
| 200% and 400% zoom (emulated) | Pass after one reflow fix |

## Defects found and fixed in this task

1. **Closed mobile menu stayed in the tab order.** Its links were off screen but
   focusable, so keyboard users tabbed through invisible links. The closed
   drawer is now hidden from the tab order and accessibility tree
   (`visibility`), the menu button has `aria-controls` and a synchronised
   `aria-expanded`, and Escape closes the menu and returns focus to the button.
2. **Navigation landmarks.** The primary navigation is labelled "Primary" and the
   drawer is a real labelled `<nav>` ("Mobile menu"). The current page link now
   carries `aria-current="page"`.
3. **Home page scrolled sideways at 320px.** The "Why the US market" heading had a
   fixed 60px inline size and an unbreakable word. It now scales fluidly and
   keeps 60px on desktop.
4. **Decorative numerals counted as low-contrast text.** The large ghost numerals
   on Services and BizCheck were real text that axe measured (about 1.4 to 1.9:1
   during their colour transition). They are now generated by CSS
   (`::before` with `content: attr(data-n)`), still hidden from assistive
   technology, and no longer present as page text.
5. **"Completed" status badge on Projects was 4.25:1.** Text colour darkened to
   pass 4.5:1.
6. **BizCheck "How It Works" button had lost its button styling** (missing `btn`
   class); fixed.
7. **BizCheck intake text clipped at 400% zoom.** A grid track grew wider than the
   viewport and an `overflow: hidden` ancestor hid the overflowing text, so
   scroll width alone looked fine. Fixed with `min-width: 0` on the grid
   children; a test now checks for clipped text at 320px on every page.
8. **Menu button invisible in forced-colours mode.** Its three bars were
   background colours, which forced colours replaces. They now use the system
   text colour in that mode.
9. **Form errors were colour-only and unfocused.** The generic message "Please
   complete the highlighted fields" relied on a border colour change and left
   focus on the submit button. Contact and BizCheck now name the fields in the
   message, mark them `aria-invalid` with `aria-describedby`, and move focus to the
   first problem field.
10. **Contact form fields had an invisible boundary (found at final review).** The
    inputs used a faint line colour with a translucent fill, giving a border
    contrast of about 1.4:1 against the card on the dark hero (WCAG 1.4.11 needs
    3:1). The fields now use the shared form-field colours, as BizCheck does
    (about 4:1 or better against the card). A browser test now measures, from rendered pixels, the
    boundary of every form control on every page. The same review fixed selected
    topic chips using the surface colour as text on the gold fill (now the on-accent
    colour) and added `aria-current="page"` to the mobile menu links.
11. **Photograph description** for the globe image no longer asserts details that
    are not clearly visible ("a warmly lit interior").

## Manual checklist results

### 1. Keyboard walkthrough

Tabbed through every page at 1280px. Stop counts: Home 31, About 25, Services 24,
Projects 24, BizCheck 38, Contact 34, 404 11. The first stop on every page is the
skip link and the last is the final footer or call-to-action link. No control
lacked an outline of at least 2px. No trap was found. At 375px the closed menu
exposes no focusable links; opening it makes them reachable, and Escape returns
focus to the menu button.

### 2. Zoom and reflow

Emulated by viewport width: 640px for 200% and 320px for 400%. No page scrolled
horizontally at either width. Text clipping was found and fixed at 320px
(defect 7). The only content wider than the viewport is the decorative service
ticker on Home, which is hidden from assistive technology and scrolls by design.

### 3. Colour and contrast

All pairings generated from the theme pass at build time. axe reports zero
violations. For the 193 "needs review" results, a rendered-pixel measurement
(`tests/a11y_browser/test_review_contrast.py`) found every one at or above 4.5:1
(3:1 for large text) at all three widths. Text in the translucent fixed header
was measured at every 350px of scroll over cream, almond, gold, white and
photographic bands. The causes axe reports are gradients, translucent layers,
decorative pseudo-elements, single glyphs and arrow symbols; none indicated a
real contrast problem once measured.

Forced colours: Chromium `forced_colors: active` emulation on Home (1280 and
375px) and Contact (1280px). Text, links, form controls, buttons, chips and the
photograph card are legible and keep visible borders. Limitation: the gold
highlight on the current navigation link and the BizCheck pill disappears
visually in this mode; the current page is still exposed to assistive technology
through `aria-current`. A visible cue in forced colours (for example a border on
the current link) is a candidate for Phase 3.

### 4. Screen reader spot check

**Not performed.** No screen reader was run in this review. The landmark
structure, labels, button state and error alert were verified through the browser
accessibility tree and DOM attributes only. Owner to complete section 4 of the
checklist with a real screen reader.

### 5. Links, images and content

Every link on every page has a descriptive name (31 to 38 links per page, 18 on
the 404 page); no generic link text, and no two links share a name while pointing
to different pages. Each photograph and the portrait carry specific alternative
text describing what is shown; decorative graphics are hidden from assistive
technology; the globe illustration has a short descriptive label.

### 6. Forms

Submitting Contact and BizCheck empty: the alert names the missing fields (for
example "Please check: Full name, Company, Work email."), each is `aria-invalid`
and tied to the message, and focus moves to the first. A malformed email is
flagged alone. Fixing the field clears its state on resubmission. The verification
widget step could not be exercised because the test browser blocks third-party
scripts; it must be checked on the live site.

### 7. Motion

With reduced motion requested no CSS animation runs on any page.

## Known limitations carried forward

- Screen reader, real OS forced colours and real zoom checks (above).
- Visible current-page cue in forced colours.
- Dark theme is generated and contrast-tested but not yet in the browser matrix (Phase 2c).
- Accessibility statement and a pause control for decorative motion (Phase 3).
